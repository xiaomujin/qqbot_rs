# cq-bot 功能全清单（迁移选择用）

> 源项目 [xiaomujin/cq-bot](https://github.com/xiaomujin/cq-bot) 的**全部业务功能**，逐条摊平，供勾选。
> 触发列写的是**源项目的实际触发方式**；本项目已开启群聊全量消息模式，因此这些触发**可以原样保留**。

---

## 前提：全量模式改变了两件事

| 原约束 | 现状 |
|---|---|
| 群聊只有 `GROUP_AT_MESSAGE_CREATE`，命令必须 @机器人 | ✅ **已解除**。全量模式下收到 `GROUP_MESSAGE_CREATE`，裸关键词触发可保留 |
| 主动推送受 1000 条/群/天 配额限制 | ⚠️ **大幅缓解**。每条群消息都带 `msg_id`，回复它可以走**被动回复**，不占主动配额。只有**无消息可依附的定时推送**才需要主动消息 |

代码侧无需改动，已支持：`event/mod.rs:133` 解析 `GROUP_MESSAGE_CREATE`，`dispatch.rs:81` 与 @ 消息同等处理。

> 注意：被动窗口是**群聊 5 分钟 / 每条消息 5 次回复**。命令响应天然落在窗口内；定时推送没有可依附的消息，仍走主动消息（配额 1000 条/群/天，日常足够）。

## 成本口径

| 标记 | 含义 |
|---|---|
| 🟢 直接 | 纯文本或纯计算，或**本项目已有等价实现** |
| 🔵 接口 | 单次 HTTP 拿数据即可，不需要画图 |
| 🟡 模板 | 需要**新写一个 resvg 模板**（源项目靠 Chromium 截图） |
| 🟠 外部 | 依赖第三方接口，**稳定性/合规不受控** |
| 🔴 阻塞 | 目标平台**没有对应能力**，需要重设计或放弃 |
